# 模钥重置雷达

中文网站、站长后台与数据库任务服务。现有 `outputs/client-design` 保留为原设计参照；正式应用位于 `src/`。

## 本机使用

1. 本机配置保存在 `.env`，不要上传或复制给其他人。新环境按 `.env.example` 填写独立随机值。`ENCRYPTION_KEY` 为随机32字节的Base64编码，数据库密码须与连接地址一致。
2. `pnpm install` → `docker compose up -d database` → `pnpm bootstrap`。
3. `pnpm build` → `pnpm start`；另一个终端运行 `pnpm worker`。开发时可用 `pnpm dev`。
4. 网站：<http://127.0.0.1:5190/>；后台：<http://127.0.0.1:5190/admin>。
5. 首次在 <http://127.0.0.1:5190/admin/setup> 自行设置唯一站长邮箱与密码。至少12位密码。初始化仅允许本机，建立账号后入口关闭；公开注册关闭。

旧预览的5189端口与正式应用5190端口相互独立。数据库只绑定本机55489端口，Docker使用本项目专属卷及网络。浏览器后台设计样例位于 `/admin/preview`，清楚标记为样例，只读且不能提交到真实数据库。

## 开始自动处理

后台“来源与任务”先验证来源，再启用轮询。固定接入官方状态、Codex 官方稳定版本发布、重置辅助归档、活动辅助归档；地址不接受任意网址。这些来源默认轮询5分钟，使用条件请求减少重复下载，来源限流按其允许时间退避，结构变化暂停发布，十五分钟后自动探测，结构恢复后续跑；人工暂停仍需手动开启。手动补采保留历史标识，不制造实时通知。

Tibo 新帖发现使用免费公开接口 FxEmbed v2，固定读取 `thsottiaux` 用户动态并包含回复，无需 X 凭据、Cookie 或付费账号。后台“来源与任务”可先验证再启用，默认每 2 分钟检查一次。旧 X 官方付费入口和真实请求已停用；原有记录保留。FxEmbed 是第三方公开转发，原帖作者、编号、时间和明确回复/引用关系经本站核对，证据仍标注辅助来源，不直接采用第三方重置结论。接口可能限流、延迟或变更；原有公开归档仍作补漏。

首次读取最近 24 小时，之后按已保存原帖编号发现新帖。每轮最多两页，保存续扫断点，未保存尾页前不推进原最高编号；连接失败保留已读内容，下一轮优先续读。分页失效从原范围重扫。验证只检查样本，不保存证据、不发布、不推进游标。429 按允许时间与退避重试，结构变化暂停发布并低频恢复探测。明确同作者回复或引用用于父链；缺链的简短完成消息等待补证，不能单独判完成。此接入不新增数据库表、环境变量或依赖。

后台“系统设置 → 智能服务”填写兼容接口地址、模型、密钥、每日次数与金额上限、每百万输入/输出单价；先以关闭状态保存，测试成功后再启用。密钥只在服务端加密保存，不回显。接口必须是公开HTTPS地址，不支持本机或内网地址。连接测试会产生一次受限调用。临时网络、限流、服务端与模型格式错误先尝试三次，再按十五分钟、三十分钟、一小时冷却恢复；预算用尽等待次日或配置调整。未配置接口时仍收集原文，安全中文、结构化官方状态与版本信息可用模板自动发布，完整翻译等待配置，不计入人工审核。

没有接口时，后台提供百炼官方开通链接及“填入推荐配置”。沿用已有北京区域固定型号方案，先由账号持有人在官方控制台开通，再将密钥填写后台。推荐按钮只填写空白表单，不覆盖已有服务、不自动保存或产生调用。费用未填完整时不能测试；连接测试成功后才能启用。接口、模型及新密钥变更后重新测试。未保存输入时，顶部刷新会提示先保存，防止丢失编辑。完整方案见 `outputs/implementation-qa/AI-SERVICE-PLAN.md`，价格与地区开通时核对。

模型明确返回截断、拒绝、过滤、资源中断或空正文时不发布；兼容接口未提供结束字段时仍进行已有结构与业务校验。已返回的实际用量先记账，即使正文不可用也不会漏记费用。长英文全文翻译仍需要真实接口及内容质量验收。

站点设置中的“自动发布明确内容”控制日常自动发布。智能服务启用后，后台自动接续未生成积压，新消息优先，历史资料分批。关闭再打开自动发布时，已核验的中文内容直接续发，不重复调用模型。

审核台默认只显示真正需要人工核对的异常。等待配置、排队、处理中和技术失败在“自动队列”查看。事件与新闻是发布后的管理记录，不是额外审批步骤。安全列表每10秒刷新，编辑期间暂停刷新。

明确产品更新可自动发布中文新闻；预告、发放中和完成声明分别核验，不把预计时间当作完成。上下文沿明确父帖关系补齐，已知原帖链接尝试官方公开嵌入补全文；截断和未提供的父关系不猜测。缺证自动等待，证据变化后重判，相同输入不重复调用。明确取消、资格调整和更正自动同步，旧错误提醒撤回；真实冲突才进入审核。新闻与福利状态分开发布，辅助归档标题不充当原帖。人工保护按字段生效，新进展不锁死整个事件。

## 数据口径

- 原文追加版本；事件关联同一轮次的消息；用量重置与重置卡各自拥有动作状态和资格。
- 文章与发布快照独立编号，首页、详情、活动和海报读取已发布结果。
- “公告称已发放”只说明公开声明，个人账户到账未观测。预计时间经过不会变成完成。
- 已保存的历史导入保留当时资料截止及上下文缺口，不能作为本次实时采集验收。
- 提醒基于关键变化生成。更换中文措辞、刷新、重采不新增发放次数或提醒。读者偏好和已读保存在本机；关闭网页后不承诺通知。
- 更正、撤回、合并、拆分要求操作原因并写入记录；并发修改返回版本冲突，保留当前编辑。

## 三个运行部分

| 部分 | 本机运行方式 | 职责 |
| --- | --- | --- |
| 网站与后台 | `pnpm start` | 页面、登录、公共及管理接口 |
| 后台任务 | `pnpm worker` | 调度、租约、采集、生成与自动发布 |
| PostgreSQL | `docker compose up -d database` | 事实、版本、任务、提醒与审计 |

没有Redis。任务存在PostgreSQL中，进程恢复后会接管过期租约。公开接口前缀 `/api/v1`，管理接口前缀 `/api/admin`。`/api/v1/health` 检查数据库读取与来源状态；后台同时显示任务失败原因。网页在前台每5秒检查轻量版本标记，有变化才取最新公开数据，并每60秒校准时间；恢复前台或网络后立即检查。该周期是发布后的检查频率，不是从原帖到发布的保证延迟。

## 验证

`pnpm typecheck`、`pnpm test`、`pnpm build`。

`pnpm test:integration` 创建独立QA数据库并运行5191端口测试服务，验证登录保护、发布、去重、版本冲突、撤回、密钥隔离等；不会创建你的站长账号。QA库保留在本项目数据库容器内，报告在 `outputs/implementation-qa/`。

`pnpm exec tsx scripts/verify-sources.ts` 实际读取三个固定来源、重复读取检查新增条数，验证成功的来源会启用本地轮询。不能据此宣称漏采率、事实准确率或长期延迟已测。

## 备份与恢复

运行 `bash scripts/backup-database.sh`，备份保存在项目内 `backups/database/`，权限仅当前用户可读。数据库包含加密密钥、用户哈希和会话，应与 `.env` 分开妥善保存。丢失加密主密钥无法解密接口密钥。

自动备份使用项目内 `scripts/backup-config.json`，样例见 `scripts/backup-config.example.json`；默认每日一次，失败后按配置重试，已有备份不自动删除。`local-runtime.mjs` 监督备份进程，`node scripts/backup-scheduler.mjs --health` 读取真实状态。备份先写 `.partial`，通过非空及恢复目录校验后才生成 `.dump`，失败产物不冒充可恢复备份。账号维护、恢复及加密主密钥保管见 `outputs/implementation-qa/BACKUP-OPERATIONS.md`。同一磁盘的本机备份不能代替离机备份。

恢复时先停止任务服务，在同一PostgreSQL实例中创建一个全新的恢复数据库；使用 `pg_restore --no-owner` 导入备份，再把独立测试配置的连接地址指向恢复库。核对原文、发布版本、任务与站长登录后，才能安排切换。不要直接清空或覆盖当前数据库；生产恢复、域名与部署由后续明确授权处理。

## 本轮边界

仅本地实现和验证。没有推送、购买或部署；没有支付或会员；微信订阅提醒代码已接入，真实账号尚未配置。微信小程序本地客户端见 `miniprogram/`，真实 AppID、接入配置、微信开发工具、真机和正式发布分别待验收。真实智能服务调用需要你的接口配置，不能用注入生成器的数据库测试替代真实模型内容质量验收。产品版本来自官方 GitHub 分页发布列表，每页五条、每轮最多三页，保存补漏断点并回看；只收录稳定版本，不依赖辅助归档。断点补漏完成前不能宣称覆盖全部历史版本。

Tibo 免费公开动态已接入。2 分钟是默认检查周期，实际新帖到本站显示的延迟仍未测量，不能承诺分钟级送达或完整历史覆盖。X 公开嵌入用于已知链接补证，公开归档保留辅助发现身份。漏采率、长期端到端延迟和真实模型事实错误率仍待测。

## 日常运行与持续观察

本机可运行 `node scripts/local-runtime.mjs` 同时托管网站、任务和备份调度进程，异常退出后自动重启，正常停止时转发退出信号。仅运行一个托管进程，避免重复监听。当前本机托管记录在 `outputs/implementation-qa/local-runtime-process.json`，不代表电脑重启后的系统自启动。备份只有在项目配置启用后执行，未启用时明确显示关闭。容器三服务配置及健康检查见 `outputs/implementation-qa/DAILY-RUNTIME.md`，尚未部署。

## 微信小程序

活动页面支持选择当天已发布条目并生成整日海报，分享链接明确携带固定版本，不随刷新、补采或更正替换内容；单日最多8条、分享地址最多1800字符，超出会明确提示。网站海报为可识别网页二维码，小程序详情海报使用微信接口返回的真正小程序码，不以网页二维码冒充。

微信功能默认关闭。先备份数据库，再经授权执行 `pnpm exec tsx scripts/migrations/wechat.ts --apply`，建立独立读者、一次性授权和发送记录三个表；该迁移不在网页请求、任务或普通初始化中偷偷执行。登录管理后台 `/admin/settings/wechat` 填写真实小程序编号、服务端密钥、实际可用模板及字段、版本和每日调用上限。密钥沿用服务端加密主密钥，不进入公开接口、小程序或日志；不需要新增环境变量。

圆码只指向固定发布版本，撤回或合并后停止生成与解析。订阅仅由用户点击发起独立微信登录、准备请求，再次主动点击微信授权；客户端会话只留在内存。每次接受最多消费一次授权，只发送之后的新关键变化；发布任务独立运行，不等待微信结果。发送前的配置或额度故障自动等待，微信明确拒绝与结果不明分别记录，结果不明停止自动重发。关闭提醒取消待发记录，已提交微信的提醒可能仍会收到。匿名登录尝试每分钟最多10次、每日最多占总调用上限四分之一（不足4次时最多1次），失败也计数，避免错误登录耗尽其他功能额度。

公共圆码及场景接口位于 `/api/v1/wechat/`；读者登录和订阅位于 `/api/wechat/`，使用独立短期会话，不复用站长登录。后台仅显示安全配置与实际发送结果。需真实账号、微信后台配置、开发工具和真机分别验收后才能启用，不能用本地模拟通过代替真正微信发送成功。

原生小程序复用本项目公开发布数据，管理后台仍由网站提供。配置和导入说明见 `miniprogram/README.md`。支持正式 HTTPS 公共接口以及微信云托管的免自购域名调用；两者都需真实接入验收，不把本机或默认测试域名当正式接口。云托管按用量收费，小程序账号并不赠送网站域名；网站及管理登录入口另行确定。官方边界及现有容器适配注意事项见 `outputs/implementation-qa/CLOUD-MINIPROGRAM-PATH-20261010.md`。

`pnpm exec tsx scripts/observe-automation.ts` 每五分钟只读记录全部已启用非人工来源的新鲜度、任务心跳、网站公开版本和真实新消息，写入项目内 `daily-observation.json/jsonl`。同时从原观察锚点复核持久化采集失败审计并按编号去重，采样之间发生后恢复的失败也会打断连续计时，晚提交记录在后续检查中补见。免费运行与模板发布分别连续观察七十二小时；断采、网站不可用或超过十分钟的采样缺口会重新计时。观测规则升级后的首个有效采样重新计时，不复用旧规则的健康时长。模板验收还需公开接口实际读到真实新消息的自动模板版本。模型生成单独计时和统计实际调用，未配置付费接口不阻塞免费链路，也不算模型验收成功。达到时长只进入待复核，仍需检查内容、采集覆盖和实际结果。

`pnpm exec tsx scripts/observe-hourly-predictions.ts` 只读核对本机不可变发布记录，在项目内独立保存小时预测观察窗口、逐次日志与评分。首次运行创建前瞻锚点，锚点之前、发布时已过期、历史补采、人工或定向消息不算新预测。每轮固定首个含时间的公开预告，后续改期不会替换评分；同事件、同动作、同类型的后续公开完成声明才作为结果。预计点的一小时内误差与最晚期限是否兑现分开统计；缺完成声明和取消分别保留，不因倒计时过期自行判完成。源码指纹发生变化则停止该窗口复核，保留旧文件。统计模型自身的快照和结果仍独立保存在既有预测表中；公开完成发言时间不代表个人账户实际到账时间。

新帖时延另有独立观察窗口，保存在 `outputs/implementation-qa/collection-observation-window.json`，状态和每轮记录为同目录的 `collection-observation.json/jsonl`。从窗口开始后发布的 Tibo 免费原文，以数据库首次记录的 `created_at` 减原帖发布时间；重复和修订只计一次，历史补采、窗口前原文和异常时间排除。`created_at` 是数据库事务时间，不等于精确提交时刻；该指标也不测量上游首次可读时间或证明完整动态流覆盖。重启保留窗口，观察文件损坏时停止并保留证据。没有新帖时统计为空，不生成虚假的速度。采集、发布及公开接口首次观测时间继续写入 `daily-publication-timings.jsonl`；上游发现时间与浏览器可见时间未测时明确标为 `NOT_MEASURED`。历史补录使用来源时间并标历史收录，不冒充实时消息。

### 公开页面轻量读取

新版网站和原生小程序使用 `GET /api/v1/bootstrap?view=home` 读取首页摘要。该摘要独立保留当前预告、用量重置与重置卡最近完成记录及最近三条动态；原文、上下文和完整固定预测在详情页读取，不修改数据库里的旧发布或冻结记录。

`GET /api/v1/version?light=1` 返回正文版本和状态版本，并支持 `If-None-Match`/304。来源采集时间变化只更新状态；发布、更正、撤回、资格、期限及来源可用性变化仍更新正文。公开 GET 查询使用约两秒缓存，并合并同时未命中的相同查询；登录、订阅和微信码请求不进入该缓存。

历史与动态使用 `view=history|news`、`filter` 和返回的 `page.nextCursor`，每次在数据库筛选二十条。切换分类重新开始分页；插入新记录不会移动已有游标。`view=detail` 按实体及指定 ID 读取完整依据，活动页按日期读取。原有无 `view` 的完整公开接口继续兼容。

客户端只在前台每五秒加最多一秒错峰检查版本，失败有限退避；倒计时与完成已过去多久在设备本地推进。容量以隔离实测和后续真实云端/国内设备结果分别报告，不把本地模拟人数当成生产承诺。

### 微信通知后的访问高峰

通知任务单次最多建立五十条，worker 最多每五秒扫描一次订阅名单，采集仍优先于通知。发送采用应用自身的滚动限速：任意一秒最多十次尝试，使用现有数据库发送记录和事务锁跨进程计数，重启不会清空限制。该上限不是微信额度，实际发送还受已有每日预算、用户一次性授权和接口耗时限制。

发送前，worker 通过现有 `BETTER_AUTH_URL` 访问实际网站的首页摘要及通知对应的固定发布详情，使预热落在网站进程而非 worker 自己的缓存。该地址必须指向可访问的正式网站；仅允许 HTTPS，或本机调试的 HTTP 回环地址，不跟随重定向、不发送读者凭据。相同发布版本的预热并发合并，成功复用两秒、失败延后五秒重试。页面不可读时保留队列，不消耗订阅授权或发送额度；撤回、拒绝、结果未知仍沿用原有保护规则。

保持至少一个运行实例可避免服务缩到零后的首次启动等待，但需由实际云端配置和账单验证。通知高峰验收应包含真实云端数据库、采集与发送同时运行、集中打开同一条链接、持续轮询和重启恢复；本地使用测试替身不会证明微信送达或真实手机表现。

`node scripts/runtime-entrypoint.mjs health-app` 根据实际 `PORT` 检查本机轻量公开版本接口，未设置时沿用本地 5190；云托管容器的 8080 不再被错误探测为 5190。HTTP 成功但缺少有效版本、重定向、数据库故障或非法端口均判失败，不输出配置或响应正文。公开查询的两秒缓存可能短暂保留数据库断开前的结果，断开验收在缓存过期后执行。

2026-10-14 的运行候选默认以 `app-worker` 在同一容器启动网站与后台任务，不新增容器服务。任一子进程意外退出时终止另一个进程并向平台返回失败，避免网站仍能访问却已停止采集；停止容器时同时通知两个进程退出，超时后结束残留进程。独立 `app`、`worker` 和健康检查模式仍保留。该运行候选需要实际部署并核对 worker 心跳，网页上线不能代替任务验收；采集来源须先通过结构验证再主动启用。
## CloudBase 公共只读适配（隔离候选）

默认仍使用原生 PostgreSQL。`RADAR_PUBLIC_READ_BACKEND=cloudbase` 仅切换公共 GET 读取，并使用 `CLOUDBASE_ENV_ID` 与仅后端持有的 `CLOUDBASE_API_KEY`。完整 CloudBase 候选须同时设置 `RADAR_STORAGE_BACKEND=cloudbase`，并安装下述认证、业务与账本结构；不能仅开启公共读取就省略原生数据库。

公共读取通过一次 STABLE RPC 获取同一数据库快照，复用现有事实与预测判定：轻量版本检查、首页摘要、20 条 SQL 游标分页、详情原文、活动、通知和固定预测读取均保留。只读接口不返回 AI/微信私有配置，也不发送微信。固定预测和原文不被摘要覆盖。

新空测试库的候选安装顺序为 `scripts/migrations/cloudbase-public-schema.sql`、`scripts/migrations/cloudbase-public-read.sql`。前者遇到已有表即失败，不覆盖或导入数据；创建时会显式移除平台默认授予后端角色的写权限，再授予 SELECT。实际云端安装/权限改变仍须当前动作授权。

隔离验证使用 `pnpm exec tsx scripts/test-cloudbase-adapter.ts`，真实受控接口验证使用 `pnpm exec tsx scripts/test-cloudbase-live.ts`。后者只读取 Git 忽略的本机配置，不输出凭证或行数据；报告留在项目已有 `outputs/implementation-qa/cloud-continuation-20261013/`。

CloudBase 失败响应保留原 HTTP 状态和用户提示，并附加固定白名单生成的 `diagnosticCode`，不显示在客户界面。例如 `CB_REJECTED_503_PGRST002` 表示网关构建数据库结构缓存时无法连接数据库，`CB_REJECTED_404_INVALID_ENV` 表示网关未识别环境，`CB_REJECTED_403_42501` 表示权限拒绝。诊断只保留已知错误码，不返回上游正文、环境地址、凭证或请求参数；未知错误标记为 `UNCLASSIFIED`。连接根因应以实际运行配置和诊断结果为准，不据此自动更换数据库、修改权限或重试写入。错误码参考 [PostgREST 官方说明](https://docs.postgrest.org/en/stable/references/errors.html)。

### CloudBase 业务写入候选（仍未部署）

隔离副本新增 `RADAR_STORAGE_BACKEND=cloudbase` 后，业务 `list/one/insert/put/transaction` 使用固定 RPC。默认仍为 native；公共读取必须同时使用 cloudbase，避免写入与展示分属不同数据库。不要把隔离验证用的 `CLOUDBASE_TEST_*` 当成运行配置。

先安装 `scripts/migrations/cloudbase-write-schema.sql` 和 `cloudbase-write-rpc.sql`，仅适用于已安装认证/公开读取结构的空 leida-test；重复执行遇到现有对象即回滚，不能据此覆盖既有表。新增 5 张空业务表、1 张私有租约表、3 个固定接口；原公开表仍只允许后端 SELECT，通过检查身份与读集的受控函数完成原子写入。禁止传入任意 SQL，不支持业务删除。

已验证原有采集、自动模板发布、失败审计、人工编辑保护、微信授权与提醒排队，以及独立预测观察写入。事务提交检查完整读集，冲突和未知结果不会被写入层自动重试；自动发布另需有效的发布租约及 worker 任务租约。未知发送结果保留并停止重发。

分页每次最多 100 行；单次响应/提交超过 1.8 MB 拒绝，每个事务最多 500 个变更，单表工作集上限 20,000 行 / 32 MiB。达到上限会明确失败，不能截断原文、历史或冻结预测。此候选是小规模验证路径，不能据此承诺长期大数据量或真实云端在线人数。

### CloudBase 管理登录、初始化与账本候选

全局管理认证、首次站长设置、后台任务及健康检查已按 `RADAR_STORAGE_BACKEND` 统一选择存储。完整 CloudBase 模式不依赖 `DATABASE_URL`；原生模式继续使用原有数据库。认证签名、加密主密钥与正确的 `BETTER_AUTH_URL` 仍需配置，不得使用示例占位值。

在上述结构安装后执行 `scripts/migrations/cloudbase-accounting.sql`，新增空 AI 账本及 4 个受控后端接口。创建时显式移除前端及后端直接写权限；计费预留、预算校验、结算通过检查身份的固定函数完成。预留固定当时价格，重复结算不覆盖结果，未知预留结果停止自动调用，不能据此声称真实付费调用已验收。

完整 CloudBase 模式执行 `pnpm bootstrap` 只补齐缺失的站点、关闭的采集来源、关闭的 AI 和空活动配置，不导入历史、不覆盖现有配置、不创建站长密码。首次站长设置仍仅允许本机；用户创建账号后该入口关闭，公开注册继续关闭。原生迁移和历史导入脚本在 CloudBase 模式会拒绝执行。

`pnpm exec tsx scripts/test-cloudbase-adapter.ts --full-app` 可检查实际生产构建的容器入口、唯一站长设置、登录、后台读取、退出、单轮 worker 和健康检查；构建应先存放在项目 QA 目录的 `cloudbase-complete-build-20261014` 中。SQL 回滚探针只在空测试库且初始配置尚未写入时执行，测试记录全部回滚。

这些结果属于隔离代码与本地验证；云端结构安装、初始化、网站部署、实际用户登录、微信送达与 AI 账单分别记录。测试不会调用真实 AI/微信或导入业务数据，不能用本地结果冒充线上验收。
